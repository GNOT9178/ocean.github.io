关于这个站，
也关于我

一个还在路上的网络安全初学者。白天上课，晚上开虚拟机打靶，周末把踩过的坑写成文章。

我是谁

叫我 Ocean 就好。目前是网络安全方向的学生／初学者，真正开始系统学习的时间不算长， 所以这个博客里的内容，绝大部分是「我搞懂之后顺手写下来的解释」，而不是「我早就懂了所以教你」。

我的学习偏向 Web 安全：从请求与响应开始，一个漏洞一个漏洞地打，一个靶场一个靶场地过。 对二进制、逆向、内网渗透目前只是知道大概，还谈不上会。

为什么开这个博客

三个理由，按重要性排序：

  • 输出会暴露没懂的地方。看视频时觉得「会了」，写笔记时才会发现连参数为什么这么传都说不清。写作是最便宜的自我检测。
  • 收藏夹不等于能力。我存了太多「以后再看」的链接，结果全变成了心理安慰。文章写完才算真的过了一遍。
  • 给自己留证据。一年后回来看，能清楚知道哪些东西当时卡了多久、后来怎么想通的。这比任何学习计划表都真实。

三条自我约定

  1. 只写自己真的动手做过的东西；转述别人的结论时，注明出处。
  2. 只测试自己搭建或明确授权的环境。公开靶场、自建虚拟机、CTF 题目，仅此三种。
  3. 每月至少一篇，写不出来就写复盘，不凑数量、不写水文。

这个站怎么搭的

没有服务器、没有数据库、没有框架，就是几个手写的 .html 文件加一份样式表， 托管在 GitHub Pages 上。好处是快、免费、改起来没有心理负担；坏处是每次写新文章都要复制一份模板—— 等文章真的多起来，我可能会换成静态站点生成器。

完整的过程写在这篇文章里：《把博客推上线：GitHub Pages 从空仓库到可访问》。

联系我

发现文章里的错误，或者想交流学习方法，欢迎在 GitHub Issues 里留言—— 这是目前唯一可靠的联系方式，我看到会回。

给同样在入门的人

如果你也是刚开始学，别把「搭博客」当成前置任务。先写第一篇，哪怕只有 300 字、只有一条命令的解释，也比等一个完美模板强。
