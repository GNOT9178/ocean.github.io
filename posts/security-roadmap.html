学习路线

网安新手路线图：我给自己排的 12 个月

从「什么都不会」到「能独立挖一个洞并写出报告」，中间需要补哪些课、打多少靶、怎么才算过关。

OOcean · 2026-11-10 · 约 12 分钟

网上关于「怎么学网安」的建议，问题不在少，而在太多而且互相矛盾：一会儿说要先学汇编，一会儿说直接上靶场， 一会儿又推荐从运维转过来。我花了很久才想明白：这些建议本身都没错，错的是它们对应的是不同的起点和不同的目标。

所以这篇文章不谈「最优路径」，只写我给自己排的路径：明确起点（零基础、有一点编程）、明确目标（做 Web 安全，能独立完成一次授权测试并写报告）、 明确时间（每周约 12 小时）。你可以直接拿走框架，再按自己的情况改。

零、先选方向，别急着学工具

网络安全不是一个专业，是十几个专业的合集。入门阶段最容易犯的错，是把某个方向的工具当成整个行业的知识。

方向主要做什么需要的底子我的选择
Web 安全 / 渗透测试 在授权范围内测网站和业务系统，找漏洞、写报告 网络 + Web + Linux + 一门脚本语言 主攻
二进制 / 逆向 分析恶意样本、挖内存漏洞（Pwn） C、汇编、操作系统、编译原理 以后再看
安全运营 / 应急 看告警、做研判、溯源、处置 系统 + 日志 + 网络流量分析 作为副线了解
合规 / 等保 按标准做差距分析、出整改方案 标准文档 + 沟通 + 业务理解 暂时不碰

我选 Web 的理由很朴素：反馈最快。改一行参数就能看到页面变化，不需要等几个月才能跑通第一个 demo；而且入门资源最丰富，卡住了基本都能搜到解释。

一、阶段 1（第 1–2 月）：把地基打平

这一阶段不碰任何「黑客工具」。三件事：网络、Linux、编程。

1.1 网络

  • TCP/IP 分层，以及数据从浏览器到服务器的完整路径；
  • TCP 三次握手、四次挥手，为什么是三次不是两次；
  • HTTP/1.1 报文结构：请求行、请求头、空行、请求体；状态码分类；
  • DNS 解析流程（递归 / 迭代），A、CNAME、MX、TXT 记录的区别；
  • 代理和 VPN 的区别（这个直接决定后面怎么配抓包）。

练习方式：装个 Wireshark，抓一次自己访问网站的全过程，然后对着抓到的包，把上面每一条讲出来。 讲不出来就是没学会。

1.2 Linux

  • 目录结构：/etc、/var/log、/proc 各自放什么；
  • 权限：rwx、umask、SUID/SGID，chmod 的八进制写法；
  • 进程与信号：ps、top、kill、nohup；
  • 日志在哪、怎么看；服务怎么起、怎么查为什么起不来；
  • 三剑客 grep、sed、awk 的基本用法。

最有效的练法：用命令行搭一套 Web 环境，而不是用集成面板。装 nginx、PHP、MySQL，把 DVWA 跑起来。

bash# 用 Docker 最快跑起一套 DVWA（只在本机 127.0.0.1 暴露）
docker run -d --name dvwa -p 127.0.0.1:8080:80 vulnerables/web-dvwa

# 看日志，确认服务真的起来了
docker logs -f dvwa

1.3 编程

只需要两件事：Python 能写小脚本、能看懂别人的 JS 和 PHP。

  • Python：文件读写、requests、socket、正则、异常处理；
  • JS：事件、DOM、fetch、同源策略；
  • PHP：至少能看懂 $_GET、$_POST、字符串拼接和 include；
  • SQL：SELECT、UNION、子查询、information_schema 是什么。

阶段验收

  • 不看笔记，说出一次 HTTP 请求里每个头的作用；
  • 能在 Linux 上从零装好并启动 DVWA，知道日志在哪；
  • 能用 Python 写一个 30 行的本机端口探测脚本（只扫 127.0.0.1）。

二、阶段 2（第 3–4 月）：Web 是怎么运转的

漏洞是「程序按照你输入的方式运行」的结果。所以必须先知道正常流程长什么样。

  • 前后端交互：表单提交、AJAX、JSON API、重定向；一次点击到底发了几个请求；
  • 身份体系：Cookie、Session、Token 的区别，为什么「登录状态」其实是一张凭证；
  • 同源策略与 CORS：浏览器的安全边界在哪里，为什么 XSS 可怕；
  • 参数来源：GET、POST、JSON、Header、Cookie、文件——每一个都是输入点；
  • 工具：浏览器开发者工具、Burp Suite 的 Proxy / Repeater / Intruder、curl。

这一阶段我最深的体会：先把 Burp 用熟，再学漏洞。因为后面所有验证，本质上都是「拦截 → 改一个地方 → 放行 → 看反应」， 这条动作不熟练，学什么漏洞都是照着别人的步骤点。

三、阶段 3（第 5–8 月）：一类一类啃漏洞

不追着「今天挖到什么洞」跑，而是按类型吃透。每一类都回答四个问题：为什么成立 / 怎么验证 / 影响多大 / 怎么修。

漏洞一句话原理练法
SQL 注入用户输入进入了 SQL 语句的语法位置sqli-labs 前 30 关 + PortSwigger Labs
XSS输入被当成 HTML/JS 执行，没有按文本处理反射型 → 存储型 → DOM 型，逐个来
CSRF浏览器会自动带上凭据，而服务端只看凭据自己写一个恶意页面打自己的靶场
文件上传只校验了前端、后缀或 Content-TypeDVWA Upload 三档难度全过一遍
文件包含路径参数可控，include 了不该包含的文件本地包含 + 伪协议，理解原理即可
SSRF服务端替你去请求了内网地址PortSwigger SSRF Labs
越权 / IDOR只验证了「登录了」，没验证「是不是你的」改 ID、改角色参数
命令 / 代码执行输入拼接进了系统命令或 eval靶场 + 审计一小段源码
逻辑漏洞流程设计有缺口（改价、重复领券、短信轰炸）自己设计业务流程找缺口
反序列化不可信数据被还原成对象，触发魔术方法先理解原理，动手放到后面

练的顺序建议按「回显明显 → 无回显 → 需要链条」推进：先做能看到报错和结果的，再做盲注、盲打，最后才是需要组合多个点的。 中间会有一段非常难受的时期：每关都卡、每关都要查。这是正常的，别在这个阶段换方向。

四、阶段 4（第 9–12 月）：内网与实战

  • 域基础：AD、域控、Kerberos 认证流程、LDAP、SMB——至少知道它们各自解决什么问题；
  • 横向移动：凭据抓取、票据、端口转发与隧道，理解「一层一层往里走」的思路；
  • 权限提升：Windows 与 Linux 的常见提权面（服务、计划任务、SUID、内核）；
  • 报告写作：执行摘要、风险定级、复现步骤、修复建议——这部分被新手严重低估；
  • 靶场：TryHackMe 的路径课、HackTheBox 的 Starting Point，按机器做完整流程。

五、每周时间怎么排

时间内容产出
工作日 1.5 小时30 分钟看理论 + 60 分钟动手当天的命令或实验记录
周六 4 小时打靶场，一次只做一台/一类复现步骤 + 截图
周日 2 小时写复盘，更新笔记一篇笔记或一段总结
每月最后一周只复习、只整理，不学新东西把散笔记合并成一篇

每周约 11–12 小时。听起来不多，但坚持一年就是 500 多小时——比「周末突击两个月然后放弃」有效得多。

六、五个最容易踩的坑

1. 只学工具，不学原理

会用扫描器不等于会渗透。工具只是把已知的验证过程自动化了，你仍然要知道它在验证什么。 判断标准很简单：把工具关掉，你还能不能手工把这个洞测出来？

2. 跳过 HTTP 直接学漏洞

这是最致命的。所有 Web 漏洞都发生在请求和响应之间，不懂报文，就只能在别人写好的 payload 里复制粘贴， 环境一变就完全不会。

3. 靶场一路点 next

打完一关却没看过源码、没想过「如果这行代码换个写法还成不成立」，等于做了个填空题。 我的做法是：每关打完，去靶场源码里找到对应的那一行，在笔记里贴出来。

4. 收集课程，而不是学完课程

存了 40G 视频的人，往往一集都没看完。宁可只跟一套教材，把它做完。

5. 不写报告

真实的授权测试里，客户看到的只有报告。你发现的漏洞再有价值，写不清楚影响范围、复现步骤和修复建议，就等于没发现。 从打第一个靶场开始，就按正式报告的结构写。

七、我实际在用的资源

用途资源说明

查漏补缺官方文档（nginx / PHP / MySQL）比二手教程可靠，习惯查文档是长期收益

八、怎么判断自己真的学会了

不用等课程学完，用这四条检验：

  • 能对着一个陌生页面，列出它的输入点，并说清每个点可能通向什么漏洞；
  • 能不看教程，在靶场里独立复现至少 10 类漏洞；
  • 能读懂一段有缺陷的代码，指出问题行并给出修复写法；
  • 能写出一份包含执行摘要、复现步骤、修复建议的报告。

边界提醒

上面所有练习都应在自建环境或明确授权的靶场平台中进行。技术本身是双刃的：同样的手法，用在授权测试里是工作， 用在别人的系统上就是违法。学之前先把边界想清楚。
